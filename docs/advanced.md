# 详细说明

本文是 [README](../README.md) 的补充，记录不适合放在首页的交互细节、迁移恢复步骤和实现边界。中文为主；英文概览见 README 的 English 部分。

## 目录选择器

点某台主机的「浏览目录」，目录面板就展开在**这台主机那一行下面**（再点一次收起），不会跑到整个列表底下；面板内再点「把当前目录做成工作区」后自动收起，新工作区直接出现在这台主机的列表里。

面板上方的筛选框边打字边过滤当前已列出的名字，不发远端请求；换目录时清空，同一目录刷新时保留。框里也可以直接输入或粘贴整条路径：框里放的是完整路径，下面列的是**最后一个 `/` 之前那层目录**的子目录，并按还没输完的那一段过滤——`/home/me/co` 列出 `/home/me` 里匹配 `co` 的目录，粘贴 `/home/me/code` 也一样。选一行或按 Enter 就把那一段补全、末尾补上 `/`，面板随即进入该目录，框里仍是完整路径；粘贴带尾斜杠的 `/home/me/code/` 直接就位。

输入过程中面板跟着路径走（面包屑是远端 realpath，符号链接和 `..` 都收成一个写法），相对路径（`a/b`、`../shared`、`home/me`）按**开始输路径时所在的目录**解析，`~` 由远端展开。路径还没补成目录时「创建工作区」不可用（title 会说明）；Esc 清空路径、停在当前目录，点「上一级」「刷新」或面包屑也会先清空路径再跳。父目录不存在或没权限时提示就在框下面，框里的内容保留着可以改。

**「新建文件夹」** 在筛选框下方展开一个输入行，回车即在该目录下建一级子目录，列表随即刷新、名字保留在输入框里，方便连着建几个；名字里带 `/` 或为空会被拦下，重名会照远端返回的结果提示。

键盘：

- 面板打开或换目录时焦点就地落在筛选框；框空着时右侧有一行提示「Tab 进目录行；按 / 回到这里」。
- 从框里按 Tab 才进目录行（Tab 走到哪一行，高亮就跟到哪一行）；在行上按 Esc 或 Backspace 回到筛选框；点过面板别处后用 `/` 回到框里（只在 SSH 主机页生效，输入框里按 `/` 照常输入）。
- ↑/↓ 在目录间移动高亮，Enter 接受高亮行（没有高亮时取唯一匹配，再取与最后一段同名的行；都没有就原地提示，不发请求）；按名字筛选时只取唯一匹配。
- Esc 先清空路径或筛选、再按一次退出输入框；Home/End 跳到首尾。

## 远端依赖安装

**bubblewrap。** Linux 上没有可用的 bubblewrap 时，可以点主机行的「安装远端沙箱依赖」。按钮按发行版执行 `sudo -n`，避免卡在密码提示。页上同时有可复制的自行安装命令：

- Debian/Ubuntu：`sudo apt-get update && sudo apt-get install -y bubblewrap`
- Fedora/RHEL：`sudo dnf install -y bubblewrap`
- Arch：`sudo pacman -S bubblewrap`
- Alpine：`sudo apk add bubblewrap`

macOS 使用系统自带的 `sandbox-exec`，没有安装按钮。探测失败时，受限 bash 需要经审批把这一次升到 `danger-full-access`。

**ripgrep。** `glob` / `grep` 需要远端有 `rg`。连接时会按远端架构上传随插件带上的二进制。本机没有该平台的包时（典型是 Windows 上的 DSH 管 Linux 远端，包管理器只装本平台的 `@vscode/ripgrep-win32-x64`），如果远端 `$HOME/.dsh-permission-remote/rg` 已经能跑 `--version`，探测直接用它，不再下载。还没有这份文件时，主机行会出现「安装 ripgrep」：按远端平台从 npm 源下载 `@vscode/ripgrep-<platform>`，取出 `package/bin/rg` 缓存到 `$DSH_HOME/cache/ripgrep/<platform>/rg`，再重新探测；上传被远端拒绝时也用同一个按钮重试。只有点这个按钮才联网，下载源在设置页填（留空用 npmjs，可填镜像）。都不想用的话，可以在远端自己安装 ripgrep，让 `rg` 出现在 `PATH` 里。

## 工作区标题、删除与恢复

每台主机下面有「已添加的工作区」，列出从这台机器创建的工作区、远端目录和会话数。可以只从 DSH 列表移除（远端文件不动），也可以把侧栏标题重新标注。

DSH 的侧栏工作区行只显示标题、没有可挂标记的 slot，所以插件把主机名写进标题：`服务器 · 目录名`。加载时只标注标题仍是目录名的那些；你改过的名字不会被自动改写。每台主机下的「标注侧栏标题」会给该主机全部工作区标注，并把旧服务器前缀换成当前的。设置页的开关 `tagWorkspaceTitles` 可以整体关掉，重新打开时会立即标注一遍。

删除主机只是把它从列表移走：工作区仍然注册在 DSH 里，标题保留原前缀。设置页的「已删除的主机」分组里可以「恢复主机」（配置和指纹都还在），也可以逐个「注销工作区」。

## 占位路径与会话边界

打开这个工作区的会话后，对话和 Permissions 与本地会话相同。相对路径按远端工作目录解析。工具结果里的路径写成占位目录，模型下一轮仍用这条路径。`working_directory` 也留在这条占位路径上：切换目录会确认远端目录存在，再把会话目录改成对应的占位路径，不会改到你这台电脑上的真实目录。

从**本地**会话切进远端路径时，占位目录会随着工作区注销留下来，而进了占位目录就等于拿到那台机器的远端 shell，所以插件不会只凭「目录还在」或「列表里已经有这个工作区」放行。`ssh_workspace` 和设置页都只注册工作区，不让当前会话进入；要在那台机器上工作，从侧栏打开。拒绝发生在目录写进会话之前，错误里也不写出占位路径，并说明这个会话不是从那台主机打开的。本地会话即使当前目录已经是某个已注册的占位目录，工具同样拒绝。

从这台主机的工作区打开的会话不受影响——在这台机器上 `cd /etc` 照常，跨主机本来也跳不过去。`workspace-write` 的可写根钉在会话头里记下的工作区目录上，不跟着当前目录走，所以打开的会话即使 `cd /` 也不会把整台机器绑成可写。这样一来，`deny` 主机也无法靠残留的占位目录绕开「拒绝所有远端读取」。

每轮的运行时上下文还会写明这条占位路径对应的远端真实目录（`Remote directory: "..."`），`working_directory` 的结果也会在占位路径下面多给一行 `(remote: /home/...)`，命令里可以直接用这条绝对路径，不必先跑 pwd。

## 环境变量来源

选「读取 bash 启动脚本」后，这条 SSH 连接上的第一条工作区命令会读一次启动文件：`/etc/profile`，然后 `~/.bash_profile`、`~/.bash_login`、`~/.profile` 里第一个能读的，再是 `/etc/bash.bashrc` 和 `~/.bashrc`。前面已经 source 过的 `~/.bashrc` 和 `/etc/bash.bashrc` 不会再读。读取时丢掉这些文件的输出，最多 10 秒。超时或失败时，这次连接后面的命令继续用 SSH 原来的环境，也不会反复重试。

读到的变量会复用，直到断开连接、切回「SSH 登录环境」，或在卡片上点「重新读取环境」。重新读取只丢掉这份缓存，不断开 SSH；下一条工作区命令会再读一次，同样最多 10 秒。bashrc 里导出的 `PATH`（例如 nvm、cargo）会保留。如果 bashrc 把 `PATH` 设成了错误的值，之后的命令会一直用这份 `PATH`，直到重新读取、断开连接或切回。

`PWD`、`OLDPWD` 和 `SHLVL` 是当前会话的状态，不会进缓存。每条命令自己的 bash 再设置它们。不读取 `~/.zshrc`。别名和函数不会保留：靠 `PATH` 找到的命令会生效，靠 shell 函数的（如 `nvm`）不会。每条用户命令仍是一个新的 bash。`ssh_exec` 不受这个设置影响，它还是 `bash -lc`。

## 迁移与恢复

设置页的「远端根目录」是本地存放所有远端工作区占位目录的位置，默认 `~/.dsh/remote`（可用 `DSH_SSH_REMOTE_ROOT` 覆盖）。把这一栏清空再保存，会回到内置默认目录。改到新目录并点「保存并迁移」时：

- 新目录不存在或是空的：把旧的 `remote` 目录整棵复制过去。
- 新目录已有内容：自动合并——缺失的补上、完全相同的跳过、同名但内容不同的文件先不覆盖，页面上会问你要「保留目标（自动合并）」还是「用旧目录覆盖」。同名但一侧是目录、另一侧是文件的情况一律不动，会列在冲突里，由你手工处理。符号链接按链接原样复制、不跟随；目标里已有的符号链接保持不动并列为冲突，避免写穿链接。
- 新目录不能放在旧目录里面（反过来也不行），否则直接报错，不会开始复制。
- 工作区里有打开着的会话时，会先提示；迁移会按远端路径把这些工作区重新注册到新占位目录下，并把已存储的会话一起搬到新位置。会话的**分组**要等下次启动 DSH 时才会恢复（工作区注册表在启动时缓存会话头，插件无法在本次进程内安全改归属）；待归组记录保存在 `~/.dsh/data/dsh-permission-remote/migration.json`（权限 0600，属于插件自身状态，不放进设置页）。正在打开的会话先留在原处（期间仍连着原服务器），关闭它们后再次保存即可补迁，但补迁后的分组同样要再下一次启动才归位。

**从旧版本升级：** 本修复只对之后发生的迁移生效。如果你的会话是在旧版本里迁移受损的（仍挂在旧占位根下、没有任何待归组记录），升级后不会被自动修好——需要手工告诉插件旧根在哪：

1. 退出 DSH；
2. 编辑 `~/.dsh/data/dsh-permission-remote/migration.json`（不存在就新建），把旧占位根加入废弃根列表，例如
   `{ "version": 1, "supersededRemoteRoots": ["<旧根绝对路径>"], "pendingSessionGrouping": [] }`；
3. 启动 DSH：启动时的补扫会把旧根下的会话搬到当前根、改好头部 cwd 并登记待归组；
4. **再启动一次** DSH，分组即恢复。

（补扫在每次启动都会跑；若旧根写错只是扫不到东西、不会损坏任何文件。）

旧目录不会被删除，确认无误后可自行清理；迁移只搬本机的占位目录，不动远端服务器上的文件。若在通用设置编辑器里直接改这个值，会立即生效但**不会**迁移旧目录——要搬目录仍请用「保存并迁移」。本次运行期间，旧目录里的路径仍按「远端占位目录」解析——挂在旧占位目录上的会话还能继续连到那台服务器；但旧目录里没有已注册工作区覆盖时，会明确报错拒绝，而不是悄悄变成本地目录。重启后旧目录不再被识别。

**主机配置备份：** 导出配置把主机列表存成 JSON（不含口令和私钥口令，它们只在凭据存储里）；导入并合并按主机 id 更新或新增，且只更新文件里真正写了的字段——只改名字的行会保留指纹、私钥路径和审批策略；地址变了会丢掉已保存的口令，文件没给新指纹时会清掉旧主机密钥。导入并替换用文件整体替换现有列表（会先确认一次；文件里没有的主机会移到「已删除主机」，可以恢复）；之前已删除、但仍有工作区的主机，即使文件没提到也会保留在「已删除主机」里。合并只并入主机行，不采用文件里的「已删除主机」记录。导入后请重新测试连接，并按需重填口令；文件里设为 `trust` 的主机会在结果里提示数量。若文件改动现有主机的地址、把主机设为 `trust`，或把 `deny` 放宽成 `ask`，页面会先询问再导入；文件新增的主机直接生效。

## 交付文件（present）

DSH 的 `present` 只认本机文件：它逐个 `stat` 参数里的路径，再把路径写进会话事件，卡片打开时读的还是本机文件系统。不接管的话，远端会话每次交付都会报 `Cannot present ...: file not found`——路径指向的占位目录里只有目录，没有文件。插件接管这个调用：先按远端确认每个文件存在、是普通文件、不超过 32 MiB，再把字节复制到对应的占位路径，最后用这些占位路径调用官方的 `present`。所以卡片、侧栏预览和「在应用中打开」拿到的是本机真实文件；同时远端那份原件不动。参数和输出仍是官方形状，`description` 原样保留。

由此有几点要知道：

- **占位路径里会多出一份文件。** 复制品落在占位根（默认 `~/.dsh/remote`）下，权限 `0600`。同一个路径再次交付会覆盖成最新内容——事件里只记路径，卡片显示的是当前那份，不覆盖就会一直显示第一次的字节。
- **超过 32 MiB 会被拒。** 报错里给出实际大小和远端真实路径，方便改用别的交付方式；截断的副本比拒绝更糟。
- **单个文件失败即整次失败。** 任一文件缺失、是目录或超限，整次交付都不写事件，不会出现「只交付了一半」。
- **只复制、不搬运。** 远端服务器上的文件不动；占位目录里的副本也不会因为远端文件后来改变而自动更新，需要重新交付一次。

## 传输工具细节

`ssh_upload` / `ssh_download` 只处理单个文件，不递归、不续传。最终组件是符号链接时两端都拒绝（远端用 `lstat`，本机也用 `lstat`，再加 `O_NOFOLLOW`），因为 `mv -f` 会替换链接本身而 `realpath` 会把有效链接解析到目标，两种语义都容易写出意外结果；中间目录是链接则按普通路径处理。FIFO、设备、socket 一律拒绝，不会被当成文件读取。

**上限与超时在设置页配置**（「设置」标签页里的「单次传输上限（字节）」和「单次传输超时（毫秒）」）：默认 32 MiB 和 120 秒，改完立即生效。填 `0` 或留空表示**不封顶 / 不限时**——不封顶时整个文件会进内存；超时/取消在本地读取、远端 stat、`~` 展开和远端写入阶段都会让调用立即返回，底层 SFTP 或 `$HOME` 探测本身无法中断，可能仍在后台跑完（`$HOME` 结果仍会缓存）。超时或取消**可能仍完成落盘**，失败也可能在远端留下同目录临时文件；已经写好的结果不回滚。超时上限是 `2147483647` 毫秒（Node 定时器的 32 位上限，再大的值会立刻触发或直接报错），超过时设置页会说明已按上限保存。超时和用户取消在上层都表现为中止，但插件会把**超时**改写成 `TimeoutError` 并在消息里写明生效的毫秒数，取消仍是 `AbortError`，模型因此能分辨是该调大设置还是别重试。

上传的远端父目录由脚本 `mkdir -p` 创建，且不会改动已有目录的权限（这里没有复用 `sftpPutFile`，那个函数会把父目录 `chmod 700`）。下载**不会**自动创建本机目录树，上级目录不存在就直接报错。

远端工作区里的会话也能调这两个工具，但那里的 `local_path` 指的是**运行 DSH 的机器**：模型看到的 `~/.dsh/remote/...` 占位路径在本机只是一个目录骨架，远端主机看不到它。要在远端会话内搬运文件，用那台机器上的 `bash`。

## 远端 run_code（PTC）

远端 `run_code` / `workflow` 使用宿主同版本官方 `@deepseek-ai/dsh-ptc-runtime-node` 的 `process.js`。插件只做四件事：定位/校验上游 worker、按 hash 上传、用 SSH 转发的 fd 7 socket 提供控制通道、把 `sandbox.confine` / `subprocess.spawn` 适配到远端。帧协议、程序运行、超时/输出上限、错误分类和工具回桥全部由官方 runtime 负责。

- 远端需要 Node.js 22+；worker 以 `process.mjs` 上传，不能直接用 `.js`（ESM 解析问题）。
- `process.env` 为空；`cwd`/相对路径在远端。支持 per-call function-body、persistent-in-memory REPL 和 vm-script（scriptPersistence）；保留状态按 state owner 留在远端进程，沙箱模式变化时由官方 runtime invalidate。
- 上游契约、manifest 与升级 runbook 见 [upstream-ptc-worker.md](upstream-ptc-worker.md)。
- 如果远端 sshd 禁用 streamlocal，会尝试 loopback TCP；两者都不可用时明确失败，不静默回退本机。

## 远程运维细节

`ssh_workspace` 做一次远端 `stat`，再按远端真实路径注册（符号链接记成它指向的目录，标题默认取这个真实路径的目录名）。`realpath` 失败则这次注册失败。它不改远端文件。它只在侧栏加一条工作区。打开这条工作区会在那台机器上开始一个会话，所以询问策略下仍和命令一样要审批。这次调用不让当前会话进入，结果里也不给出占位目录。要在那台机器上工作，从侧栏打开。文件系统根 `/` 不能注册，真实路径解析成 `/` 时同样拒绝：那一棵会盖住整台机器。对同一个远端真实路径重复添加不会产生第二行，保留已有的标题，结果里会说明它已经注册过。

运维工具的前提：

- 目标主机必须已经在设置里信任过指纹，否则连接失败
- `ssh_exec` 用 `bash -lc`，会读登录 shell 的 profile，这样 `PATH` 里才有 `systemctl`、`docker` 这类命令；profile 若往 stdout 打东西，会出现在命令输出里
- `sudo` 只能走免密（`sudo -n`）。SSH 非交互执行没有 TTY，需要口令的 `sudo` 会卡住
- 只支持直连的 Linux 或 macOS；不支持跳板机和 Windows 远端
- 上传和下载只处理单个文件：不跟目录、不续传，单次上限和超时见上面的设置项
- 网络中断时，正在执行的远端命令会失败；已经写入的文件留在远端，不会回滚

## 侧栏终端

在远端工作区里，右侧栏的终端连的是那台服务器，不是你这台电脑：新建终端时 shell 菜单里列的是远端 `$SHELL` 和远端装了的 `bash` / `zsh` / `fish` / `sh`，标签名带主机名（`lo · zsh`）。缩放、滚屏、复制、刷新页面后重连都由 DSH 原来的终端界面负责。

- **连接是共享的。** 一个标签页一条 SSH 通道，和文件传输、远端命令共用这台主机的那一条连接。OpenSSH 默认 `MaxSessions 10`，而 DSH 每个会话最多 8 个终端。通道占满时新标签页会报这台主机拒绝再开一个 SSH 会话；只关侧栏终端不一定腾得出名额，也可以在远端调高 `MaxSessions`。
- **不跟随后续的 `working_directory`。** 已经开着的终端留在打开时那个远端目录；新开的用当时的目录。占位子目录不存在时，新建终端会先把它建出来，这样不会退回工作区根。建不出来时仍由 DSH 退回工作区根。
- **断线即结束。** 连接断了终端就结束，不会自动重连，也没有回滚：关掉标签页重开一个即可。
- **只有侧栏接上了。** 模型侧的 `terminal_open` 在远端工作区里会直接报错并提示改用 `bash` 或侧栏终端——它请求的是本机 PTY 后端，会把 shell 开在你这台电脑的占位目录里。`terminal_send` / `terminal_read` / `terminal_list` 不动：它们操作的是已经存在的终端。

## 可选的 `apply_patch` / `str_replace_editor`

DSH 0.2.2 还有两个可选的文件工具，在远端工作区里同样落在这台机器上。两者默认都关着，插件不会替你启用，要在预设或组合里自己打开：把 `@deepseek-ai/dsh-tool-fs` 的 `applyPatch` 设为 `true` 才注册 `apply_patch`（所有官方预设都默认 `false`）；`@deepseek-ai/dsh-tool-str-replace-editor` 是独立包，只在自定义组合里挂载，官方预设不带它。

路径写法：

- `apply_patch` 的路径按会话工作目录（本机占位目录）解析，也可以直接给绝对占位路径，或直接写远端真实绝对路径（例如 `/srv/app/a.ts`，按远端主机解析）。
- `str_replace_editor` 只收绝对路径：把 `read` 或右侧栏文件树返回的占位路径原样传回去。若给了它一个远端真实绝对路径，插件会把它改写成同一台主机对应的占位路径，绝不会在本机按这个名字读写文件；若该工具的转发层没有挂载，这类调用会被直接拒绝，同样不会碰本机文件。

行为：`apply_patch` 的新增、更新、删除、移动，和编辑器的 `view`、`create`、`str_replace`、`insert`，都在远端执行，并遵守会话的 Permissions 档位、审批卡片和远端沙箱，删除与移动也不例外。整个补丁先整体预检，再按顺序逐条提交；中途失败不会回滚，已提交的操作留在远端。一次「移动」若已发布目标、却删不掉源文件，目标保留，调用只报告这一步失败。

限制：只处理 UTF-8 文本，不支持二进制；没有回滚。`str_replace_editor` 没有一次性的 `sandbox_permissions` / `justification` 提权，请用会话里已经设好的常驻 Permissions 档位。移动涉及两个路径，不是原子操作；删除只涉及一个路径。

## 其它实现说明

**左侧文件列表与右侧文件树。** 对话里的读文件、改文件、搜索和运行命令发生在远端。左侧的文件列表，以及输入框里的 `@` 补全，仍用本机文件系统扫占位目录，列不出远端文件。右侧栏的文件树列出远端目录里的内容，标题仍是这条占位路径，自动刷新不可用。手动刷新会再向远端要这一层的名字；文件是否存在、大小这些属性在大约 5 秒内可能仍是刚才的结果。用户上传的非图片文件会先复制到远端 `~/.dsh-permission-remote/uploads/`，模型看到的是远端绝对路径。

**Windows 上的 DSH。** DSH 本身跑在 Windows 上时，远端工作区的对话只暴露远端 `bash`。`pwsh`、`powershell`、`cmd` 不会出现在原生工具列表里，官方那段 Windows 进程结束说明（`tool:pwsh`）在停在这个工作区时也会被盖住。回到本机目录后，这些 Windows 工具和原来的说明恢复。`minimal` 这类把提示词写成完整 persona 的预设不会被改写；挡住 Windows shell 的是工具列表过滤和执行守卫。内置预设的 `pwsh` 在祖先层，进入远端时会被从原生工具列表和 `ptc` SDK 正文里去掉。注册在 agent 本层的 `pwsh` 去不掉：SDK 正文仍可能列出它，原生列表会被滤掉，调用会被拒绝。文件工具的参数继续用工具返回的占位路径。

**运行代码与项目说明文件。** 模型用「运行代码」时，如果会话的工作目录是远端占位目录，程序由 SSH 主机上的官方 PTC worker 执行，不是本机那份；本地会话仍然在本机执行。会话读取项目里的 `AGENTS.md`、`CLAUDE.md`（以及同名的 `.local`）时走文件系统接口，占位路径会读到远端那一份。`$DSH_HOME/AGENTS.md` 这种不在占位根下的全局文件仍是本机。每轮组装提示词会沿祖先目录对这些文件多做几次远端查询。提示词内容和本机那份不一样，已经缓存的前缀对不上。

**连接边界。** 目前只能直接连接一台 Linux 或 macOS。不能经跳板机连接，也不能把 Windows 当作远端。网络中断时，正在进行的操作会失败。已经写到远端的文件会留在那里：重新连上之后不会再写一遍，也不会自动撤回。远程工作区里的 `bash`、`read`、`write`、`edit` 只能操作那台机器；要在当前本地工作区操作另一台主机，用 `ssh_hosts` / `ssh_exec` / `ssh_read` / `ssh_write` / `ssh_upload` / `ssh_download` / `ssh_workspace`。

**Linux 沙箱。** 要让命令遵守当前权限，需要在那台机器上安装 bubblewrap。设置页可以代为安装，页面上也有可以自己执行的命令。
