# 详细说明

本文是 [README](../README.md) 的补充，记录不适合放在首页的交互细节、迁移恢复步骤和实现边界。中文为主；英文概览见 README 的 English 部分。

## 目录选择器

点某台主机的「浏览目录」，目录面板就展开在**这台主机那一行下面**（再点一次收起），不会跑到整个列表底下；面板内再点「把当前目录做成工作区」后自动收起，新工作区直接出现在这台主机的列表里。

面板上方的筛选框边打字边过滤当前已列出的名字，不发远端请求；换目录时清空，同一目录刷新时保留。框里也可以直接输入或粘贴整条路径：框里放的是完整路径，下面列的是**最后一个 `/` 之前那层目录**的子目录，并按还没输完的那一段过滤——`/home/me/co` 列出 `/home/me` 里匹配 `co` 的目录，粘贴 `/home/me/code` 也一样。选一行或按 Enter 就把那一段补全、末尾补上 `/`，面板随即进入该目录，框里仍是完整路径；粘贴带尾斜杠的 `/home/me/code/` 直接就位。

输入过程中面板跟着路径走（面包屑是远端 realpath，符号链接和 `..` 都收成一个写法），相对路径（`a/b`、`../shared`、`home/me`）按**开始输路径时所在的目录**解析，`~` 由远端展开。路径还没补成目录时「创建工作区」不可用（title 会说明）；Esc 清空路径、停在当前目录，点「上一级」「刷新」或面包屑也会先清空路径再跳。父目录不存在或没权限时提示就在框下面，框里的内容保留着可以改。

**「新建文件夹」** 在筛选框下方展开一个输入行，回车即在该目录下建一级子目录，列表随即刷新、名字保留在输入框里，方便连着建几个；名字里带 `/` 或为空会被拦下，重名会照远端返回的结果提示。

键盘：

- 面板打开或换目录时焦点就地落在筛选框；框空着时右侧有一行提示「Tab 进目录行；按 / 回到这里」。
- 从框里按 Tab 才进目录行（Tab 走到哪一行，高亮就跟到哪一行）；在行上按 Esc 或 Backspace 回到筛选框；点过面板别处后用 `/` 回到框里（只在 SSH 主机页生效，输入框里按 `/` 照常输入）。
- ↑/↓ 在目录间移动高亮，Enter 接受高亮行（没有高亮时取唯一匹配，再取与最后一段同名的行；都没有就原地提示，不发请求）；按名字筛选时只取唯一匹配。
- Esc 先清空路径或筛选、再按一次退出输入框；Home/End 跳到首尾。

## 远端依赖安装

**bubblewrap。** Linux 上没有可用的 bubblewrap 时，可以点主机行的「安装远端沙箱依赖」。按钮按发行版执行 `sudo -n`，避免卡在密码提示。页上同时有可复制的自行安装命令：

- Debian/Ubuntu：`sudo apt-get update && sudo apt-get install -y bubblewrap`
- Fedora/RHEL：`sudo dnf install -y bubblewrap`
- Arch：`sudo pacman -S bubblewrap`
- Alpine：`sudo apk add bubblewrap`

macOS 使用系统自带的 `sandbox-exec`，没有安装按钮。探测失败时，受限 bash 需要经审批把这一次升到 `danger-full-access`。

**ripgrep。** `glob` / `grep` 需要远端有 `rg`。连接时会按远端架构上传随插件带上的二进制。本机没有该平台的包时（典型是 Windows 上的 DSH 管 Linux 远端，包管理器只装本平台的 `@vscode/ripgrep-win32-x64`），如果远端 `$HOME/.dsh-permission-remote/rg` 已经能跑 `--version`，探测直接用它，不再下载。还没有这份文件时，主机行会出现「安装 ripgrep」：按远端平台从 npm 源下载 `@vscode/ripgrep-<platform>`，取出 `package/bin/rg` 缓存到 `$DSH_HOME/cache/ripgrep/<platform>/rg`，再重新探测；上传被远端拒绝时也用同一个按钮重试。只有点这个按钮才联网，下载源在设置页填（留空用 npmjs，可填镜像）。都不想用的话，可以在远端自己安装 ripgrep，让 `rg` 出现在 `PATH` 里。

## 工作区标题、删除与恢复

每台主机下面有「已添加的工作区」，列出从这台机器创建的工作区、远端目录和会话数。可以只从 DSH 列表移除（远端文件不动），也可以把侧栏标题重新标注。

DSH 的侧栏工作区行只显示标题、没有可挂标记的 slot，所以插件把主机名写进标题：`服务器 · 目录名`。加载时只标注标题仍是目录名的那些；你改过的名字不会被自动改写。每台主机下的「标注侧栏标题」会给该主机全部工作区标注，并把旧服务器前缀换成当前的。设置页的开关 `tagWorkspaceTitles` 可以整体关掉，重新打开时会立即标注一遍。

删除主机只是把它从列表移走：工作区仍然注册在 DSH 里，标题保留原前缀。设置页的「已删除的主机」分组里可以「恢复主机」（配置和指纹都还在），也可以逐个「注销工作区」。

## 占位路径与会话边界

打开这个工作区的会话后，对话和 Permissions 与本地会话相同。相对路径按远端工作目录解析。工具结果里的路径写成占位目录，模型下一轮仍用这条路径。`working_directory` 也留在这条占位路径上：切换目录会确认远端目录存在，再把会话目录改成对应的占位路径，不会改到你这台电脑上的真实目录。

从**本地**会话切进远端路径时，占位目录会随着工作区注销留下来，而进了占位目录就等于拿到那台机器的远端 shell，所以插件不会只凭「目录还在」或「列表里已经有这个工作区」放行。`ssh_workspace` 和设置页都只注册工作区，不让当前会话进入；要在那台机器上工作，从侧栏打开。拒绝发生在目录写进会话之前，错误里也不写出占位路径，并说明这个会话不是从那台主机打开的。本地会话即使当前目录已经是某个已注册的占位目录，工具同样拒绝。

从这台主机的工作区打开的会话不受影响——在这台机器上 `cd /etc` 照常，跨主机本来也跳不过去。`workspace-write` 的可写根钉在会话头里记下的工作区目录上，不跟着当前目录走，所以打开的会话即使 `cd /` 也不会把整台机器绑成可写。这样一来，`deny` 主机也无法靠残留的占位目录绕开「拒绝所有远端读取」。

每轮的运行时上下文还会写明这条占位路径对应的远端真实目录（`Remote directory: "..."`），`working_directory` 的结果也会在占位路径下面多给一行 `(remote: /home/...)`，命令里可以直接用这条绝对路径，不必先跑 pwd。

## 环境变量来源

选「读取 bash 启动脚本」后，这条 SSH 连接上的第一条工作区命令会读一次启动文件：`/etc/profile`，然后 `~/.bash_profile`、`~/.bash_login`、`~/.profile` 里第一个能读的，再是 `/etc/bash.bashrc` 和 `~/.bashrc`。前面已经 source 过的 `~/.bashrc` 和 `/etc/bash.bashrc` 不会再读。读取时丢掉这些文件的输出，最多 10 秒。超时或失败时，这次连接后面的命令继续用 SSH 原来的环境，也不会反复重试。

读到的变量写到远端 `~/.dsh-permission-remote/login-env.sh`（目录 `0700`，文件 `0600`）。之后每条工作区 `bash` 只 `source` 这个文件，不把变量放进命令行。发布失败时这条命令仍用 SSH 环境，下一条会再试着写文件；捕获失败则不会反复读启动脚本。

读到的变量会复用，直到断开连接、切回「SSH 登录环境」，或在卡片上点「重新读取环境」。重新读取只丢掉这份缓存，不断开 SSH；下一条工作区命令会再读一次，同样最多 10 秒。bashrc 里导出的 `PATH`（例如 nvm、cargo）会保留。如果 bashrc 把 `PATH` 设成了错误的值，之后的命令会一直用这份 `PATH`，直到重新读取、断开连接或切回。

`PWD`、`OLDPWD` 和 `SHLVL` 是当前会话的状态，不会进缓存。每条命令自己的 bash 再设置它们。不读取 `~/.zshrc`。别名和函数不会保留：靠 `PATH` 找到的命令会生效，靠 shell 函数的（如 `nvm`）不会。每条用户命令仍是一个新的 bash。`ssh_exec` 不受这个设置影响，它还是 `bash -lc`。

## 迁移与恢复

设置页的「远端根目录」是本地存放所有远端工作区占位目录的位置，默认 `~/.dsh/remote`（可用 `DSH_SSH_REMOTE_ROOT` 覆盖）。把这一栏清空再保存，会回到内置默认目录。改到新目录并点「保存并迁移」时：

- 新目录不存在或是空的：把旧的 `remote` 目录整棵复制过去。
- 新目录已有内容：自动合并——缺失的补上、完全相同的跳过、同名但内容不同的文件先不覆盖，页面上会问你要「保留目标（自动合并）」还是「用旧目录覆盖」。同名但一侧是目录、另一侧是文件的情况一律不动，会列在冲突里，由你手工处理。符号链接按链接原样复制、不跟随；目标里已有的符号链接保持不动并列为冲突，避免写穿链接。
- 新目录不能放在旧目录里面（反过来也不行），否则直接报错，不会开始复制。
- 工作区里有打开着的会话时，会先提示；迁移会按远端路径把这些工作区重新注册到新占位目录下，并把已存储的会话一起搬到新位置。会话的**分组**要等下次启动 DSH 时才会恢复（工作区注册表在启动时缓存会话头，插件无法在本次进程内安全改归属）；待归组记录保存在 `~/.dsh/data/dsh-permission-remote/migration.json`（权限 0600，属于插件自身状态，不放进设置页）。正在打开的会话先留在原处（期间仍连着原服务器），关闭它们后再次保存即可补迁，但补迁后的分组同样要再下一次启动才归位。

**从旧版本升级：** 本修复只对之后发生的迁移生效。如果你的会话是在旧版本里迁移受损的（仍挂在旧占位根下、没有任何待归组记录），升级后不会被自动修好——需要手工告诉插件旧根在哪：

1. 退出 DSH；
2. 编辑 `~/.dsh/data/dsh-permission-remote/migration.json`（不存在就新建），把旧占位根加入废弃根列表，例如
   `{ "version": 1, "supersededRemoteRoots": ["<旧根绝对路径>"], "pendingSessionGrouping": [] }`；
3. 启动 DSH：启动时的补扫会把旧根下的会话搬到当前根、改好头部 cwd 并登记待归组；
4. **再启动一次** DSH，分组即恢复。

（补扫在每次启动都会跑；若旧根写错只是扫不到东西、不会损坏任何文件。）

旧目录不会被删除，确认无误后可自行清理；迁移只搬本机的占位目录，不动远端服务器上的文件。若在通用设置编辑器里直接改这个值，会立即生效但**不会**迁移旧目录——要搬目录仍请用「保存并迁移」。本次运行期间，旧目录里的路径仍按「远端占位目录」解析——挂在旧占位目录上的会话还能继续连到那台服务器；但旧目录里没有已注册工作区覆盖时，会明确报错拒绝，而不是悄悄变成本地目录。重启后旧目录不再被识别。

**主机配置备份：** 导出配置把主机列表存成 JSON（不含口令和私钥口令，它们只在凭据存储里）；导入并合并按主机 id 更新或新增，且只更新文件里真正写了的字段——只改名字的行会保留指纹、私钥路径和审批策略；地址变了会丢掉已保存的口令，文件没给新指纹时会清掉旧主机密钥。导入并替换用文件整体替换现有列表（会先确认一次；文件里没有的主机会移到「已删除主机」，可以恢复）；之前已删除、但仍有工作区的主机，即使文件没提到也会保留在「已删除主机」里。合并只并入主机行，不采用文件里的「已删除主机」记录。导入后请重新测试连接，并按需重填口令；文件里设为 `trust` 的主机会在结果里提示数量。若文件改动现有主机的地址、把主机设为 `trust`，或把 `deny` 放宽成 `ask`，页面会先询问再导入；文件新增的主机直接生效。

## 交付文件（present）

DSH 的 `present` 只认本机文件：它逐个 `lstat` / `resolve` / `stat` 参数里的路径，把 `processPath` 的结果写进会话事件，卡片打开时读的还是本机文件系统。不接管的话，远端会话每次交付都会报 `Cannot present ...: file not found`——路径指向的占位目录里只有目录，没有文件。插件接管这个调用：先按远端确认每个文件存在、是普通文件、不超过上限，再**流式**把字节写到本机的交付快照，最后用快照路径调用官方的 `present`。参数和输出仍是官方形状，`description` 原样保留。

### 快照是内容寻址、不可变的

副本落在 `<远端占位根>/.deliverables/<sha256>/<文件名>`（默认 `~/.dsh/remote/.deliverables`），目录 `0700`、文件 `0600`。

- **同一份内容只存一份。** 字节的 SHA-256 就是目录名，所以同样的文件第二次交付会直接复用，不会重写。
- **旧卡片永远不会被新内容顶掉。** 文件改过以后再交付，得到的是另一个 hash 目录里的新副本；上一张卡片指向的那份字节一个字节都不变。这是和旧版本最大的差别：旧版本按占位路径原地覆盖，同一路径第二次交付会把第一张卡片的内容换掉。
- **只复制、不搬运。** 远端服务器上的文件不动，插件从不写远端。快照也不会因为远端文件后来改变而自动更新，需要重新交付一次。
- **快照只读。** 模型对快照路径调 `write` / `edit` / `apply_patch` / 删除或移动会被拒绝（`FS_PERMISSION_DENIED`），也不能把工作目录切进去：交付件是冻结的，改它等于改一张已经发出去的卡片。

### 上限跟随设置页，另有快照硬顶

单文件上限取「设置 → 单次传输上限（字节）」的值，**另有 256 MiB 的交付快照硬顶**。设置里的字节填 `0` 时，对话上传、`ssh_upload`、`ssh_download` 没有字节上限，但「单次传输超时」仍然生效，默认 120 秒到点会停。交付仍以 256 MiB 为上限：`present` 由模型直接调用、不经审批，副本写在运行 DSH 的这台机器上。快照目录打不开时，这一份会整段放进内存，上限同样是 256 MiB。超限时错误会写明是设置值还是硬顶生效，并给出远端真实路径和实际大小。

默认设置就是 32 MiB，所以默认行为和以前一样；把设置调大，交付上限才会跟着涨到 256 MiB。

**和应用内预览的上限不是一回事。** 侧栏和应用内全文预览走 `workspaceFiles`，它自己的整文件读取上限默认是 32 MiB。所以一个 100 MiB 的交付件可以正常交付、卡片正常、用系统应用打开也正常，但在应用内点"预览"会报 too-large。要预览大文件请调大那个上限，或者直接用系统应用打开。

### 整批要么全成，要么什么都不留

字节先流式写进 `<快照根>/.tmp/` 的临时文件（`wx` 创建、`0600`、边写边算 SHA-256），**全部文件都成功之后**才逐个 rename 发布。任一文件缺失、是目录、非普通文件、超限或在读取过程中变短，整次交付都不写事件，临时文件清理掉，已经存在的快照一个字节不动。

**回退模式同样先读完再写。** 当宿主拿不到可验证的快照路径时（见下），副本落到占位路径，但同样是「全部读完再统一写」：第二个文件失败不会留下第一个的副本。

有一处例外要知道：官方的 `present` 自己还有一条"每次最多 N 个文件"的限制（默认 8，插件读不到这个配置）。超过时官方会拒绝，而这时快照可能已经落盘——它会留成一份没人引用的孤儿副本，30 天后按过期回收。

### 什么时候过期、占多少磁盘

快照按**目录 mtime** 保留 30 天，超期整目录删除。打开卡片不会刷新这个时间（卡片打开不经过插件），所以一张放了一个多月的卡片可能打不开——那是过期了，重新交付一次即可。

**所有快照目录合计上限 1 GiB**（含迁移前旧根下的那些）。超出时按目录 mtime 从旧到新删除，直到降回预算以内。这不是「最近最少使用」——打开卡片不经过插件，插件观察不到使用——而是「最久没有新交付」，最旧的那份最不可能还挂在屏幕上。它只是防磁盘被填满的兜底：单次交付上限 256 MiB，正常使用远到不了 1 GiB，真的触发说明有人反复交付了大量不同内容。

崩溃遗留的临时文件（`<快照根>/.tmp/*.part`）按 **1 小时**回收，不必等 30 天。

**卸载插件不会删除已经交付的快照**，重启 DSH、切换远端根之后旧卡片仍然能打开。切换远端根时，旧根下的快照原地保留（迁移不复制也不统计这棵树），旧卡片的路径仍然落在旧根里，所以照样能开——过期回收也会照看到旧根，所以它们最终仍会被清理。

### 文件名

快照里的文件名取远端文件的基名。Windows 上不能用的名字（`CON`、`NUL`、带 `<>:"|?*` 的名字、以点或空格结尾的名字）会加一个 hash 前缀或把非法字符换成下划线，所以卡片上显示的名字可能和远端那份略有出入。同名不同内容不会互相覆盖，hash 目录已经保证了唯一性。

## 传输工具细节

`ssh_upload` / `ssh_download` / `ssh_copy` 只处理单个文件，不递归、不续传。最终组件是符号链接时两端都拒绝（远端用 `lstat`，本机也用 `lstat`，再加 `O_NOFOLLOW`），因为 `mv -f` 会替换链接本身而 `realpath` 会把有效链接解析到目标，两种语义都容易写出意外结果；中间目录是链接则按普通路径处理。注意这是**检查时刻**的保证：SFTP v3 没有 `O_NOFOLLOW`，检查之后把最终组件替换成符号链接的 TOCTOU 仍无法防住。FIFO、设备、socket 一律拒绝，不会被当成文件读取。下载的本机临时文件用独占创建（`wx`、`0600`），临时路径上预先种的符号链接不会被跟随，残留的旧临时文件也不会被截断后沿用它原来的权限。Windows 上覆盖已有目标时，对瞬时的 `EACCES` / `EBUSY` / `EPERM` 会做有限次重试。

**上限与超时在设置页配置**（「设置」标签页里的「单次传输上限（字节）」和「单次传输超时（毫秒）」）：默认 32 MiB 和 120 秒，改完立即生效。对话上传、`ssh_upload`、`ssh_download`、`ssh_copy` 共用这两项。上传和跨主机复制按约 1 MiB 的在途字节预算分段，避免每一小块都等一次确认；每包上限取目标服务器的 `_maxWriteLen`，但被夹在 64 KiB 到 256 KiB 之间（小于 8 KiB 或未报告时回退 64 KiB）。下载仍是一块读完再读下一块。字节填 `0` 或留空只取消**字节**上限，文件不再整份进内存，但默认 120 秒超时仍然生效：慢链路或大文件会先报超时，而不是一直写到磁盘满（`ENOSPC`）。超时也填 `0` 才不限时，那时才会写到磁盘满。`present` 仍是单文件 256 MiB、全部快照合计 1 GiB；`read` / `edit` 的文本和版本哈希仍是 32 MiB，都不看这项设置。超时/取消在本地读取、远端 stat、`~` 展开和远端写入阶段都会让调用立即返回，底层 SFTP 或 `$HOME` 探测本身无法中断，可能仍在后台跑完（`$HOME` 结果仍会缓存）。超时或取消**可能仍完成落盘**，失败也可能在远端留下同目录临时文件；已经写好的结果不回滚。超时上限是 `2147483647` 毫秒（Node 定时器的 32 位上限，再大的值会立刻触发或直接报错），超过时设置页会说明已按上限保存。`ssh_upload` / `ssh_download` / `ssh_copy` 会把**超时**改写成 `TimeoutError` 并在消息里写明生效的毫秒数，用户取消仍是 `AbortError`。对话上传到点会删掉远端临时文件，记一条带同样毫秒数的警告，这一轮对话继续，该附件不会变成远端路径。登录环境快照、PTC worker 和 ripgrep 二进制不套这个超时。

上传的远端父目录由脚本 `mkdir -p` 创建，且不会改动已有目录的权限（这里没有复用 `sftpPutFile`，那个函数会把父目录 `chmod 700`）。下载**不会**自动创建本机目录树，上级目录不存在就直接报错。

远端工作区里的会话也能调这两个工具，但那里的 `local_path` 指的是**运行 DSH 的机器**：模型看到的 `~/.dsh/remote/...` 占位路径在本机只是一个目录骨架，远端主机看不到它。传占位路径过去会在审批之前就被拒绝，并提示改用 `ssh_copy`（`local_path` 不能有一种以上含义：同名文件确实存在时，静默传错文件比报错糟糕得多）。在远端会话里要把文件搬到另一台主机，用 `ssh_copy`；`bash` 里直接 `scp` / `rsync` 仍是备选，但它绕开这两道闸门，凭证也未必在那台机器上。

### `ssh_copy`：远端 A → 远端 B

`ssh_copy` 在两条 SFTP 通道之间直接搬运字节，**不落运行 DSH 的这台机器的磁盘，也不把整个文件读进内存**。底层是 `ssh-pool.ts` 里的 `streamChunksToSftp()`：本机上传、跨主机复制、对话上传（`sftpPutFile`）共用同一个分块写入器，在途按字节预算控制、`limitExceeded` 语义一致；但源端块大小不同（跨主机复制固定 64 KiB，本机上传按目标服务器包大小），实际在途量会随目标包大小变化。

- **主机怎么定。** 源端有三种写法：`source_path` 是占位路径时，主机从路径第二段取（显式给了 `source_host` 就必须一致，否则报错）；否则用显式 `source_host`；两者都没有时，用当前会话工作目录所在的那台远端主机（取的是**实时**工作目录，`working_directory` 移动过也跟着走）。本地工作区里既无占位路径、又没给 `source_host` 时直接报错。`target_host` 必填：写侧的目标不靠推断。
- **路径怎么定。** 远端绝对路径直接用；`~` / `~/` 用**那一端主机自己**的 `$HOME` 展开（源、目标各查各的）；源端相对路径锚在会话的远端目录上，但 `target_path` 没有可锚定的 base，相对路径会被拒绝，请用绝对路径或 `~/`。目标端也可以传占位路径，但必须属于 `target_host`，否则报错。
- **两道闸门不同。** 源端按读放行，和 `ssh_read` 一致：`deny` 和未信任直接拒绝，不额外审批。目标端按写，和 `ssh_write` / `ssh_upload` 一致：`ask` 主机需要 `danger-full-access` 或一次审批，卡面同时写明两端（`copy A:src to B:dst`）。因此「目标 trust + 源 ask」这种组合可以在不弹 A 的审批的情况下把 A 的文件搬走——这是刻意的选择，和读取工具保持同一套策略，不是遗漏。
- **拒绝清单。** 源端必须是普通文件（`lstat`，符号链接 / 目录 / FIFO / 设备一律拒绝，文件大小先对上限预检）；目标端不允许是目录或符号链接；两端任一端是 `/`、或同一台主机上源和目标是同一个规范化路径，都在读字节之前拒绝。
- **失败清理。** 每次上传/复制都用**本次传输自己的 SFTP 通道**（`openSftpLease`），不与 `ssh_read`、文件树、PTC 文件操作共用。目标端先写同目录临时文件，成功后 `mv -f` 替换并保留原权限位。`close()` 在 `session.end()` 之后用完整的 5 秒清理预算等**服务端确认这条通道关闭**（`session.closed`）——250 毫秒比广域网往返短，关掉本地通道不等于服务器已经处理完排在前面的 `OPEN`。只有拿到这个确认，才在另一条 exec 通道上跑 `rm -f`；`rm` 不带已中止的 signal，否则清理通道会先被关掉。这样迟到的 SFTP `OPEN` 不可能在 `rm` 之后重建临时文件。`ssh_upload`/`ssh_copy`/`ssh_download`/对话上传共用同一套 lease 收尾；通道始终没确认关闭时，错误里会带上临时文件路径，提示可能有残留，且不会去 `mv` 发布一个可能不完整的文件。
- **连接占用。** 跨主机复制同时持有源、目标各一条连接，因此要求连接池 `maxConnections`（默认 4，目前只在插件配置里可改，设置页没有这一项）至少为 2。一条槽只在连接关闭时归还，而复制期间第一条连接不可能关闭，所以 `ssh_copy` 先按「源/目标是否已在池里」算出还需要几条新连接，空闲槽不够就在审批之前直接报「连接槽不足」，目标腿连之前再查一次，避免第二台主机在 `reserve()` 里排队到超时（超时填 `0` 时更是永远不返回）。其它调用仍按原来的方式排队：配置了超时的话，那个调用会按自己的超时先返回，排队位置留给下一个调用者，不会波及同主机上已经建立的连接；超时填 `0` 时只能等连接释放或手动取消。两台主机可以是同一台（按普通复制处理），那样只占一条。

## 远端 run_code（PTC）

远端 `run_code` / `workflow` 使用宿主同版本官方 `@deepseek-ai/dsh-ptc-runtime-node` 的 `process.js`。插件只做四件事：定位/校验上游 worker、按 hash 上传、用 SSH 转发的 fd 7 socket 提供控制通道、把 `sandbox.confine` / `subprocess.spawn` 适配到远端。帧协议、程序运行、超时/输出上限、错误分类和工具回桥全部由官方 runtime 负责。

- 远端需要 Node.js 22+；DSH 0.2.2-rc.2 的 worker 引入 `node:module` 的 `registerHooks`（该 API 自 22.15 / 23.5 才有），因此配 rc.2 的宿主要求远端 **22.15+（23.0–23.4 不含该 API，23.5+ 或 24+ 也可）**。下限不写死在版本标签上，而是从即将上传的 `process.js` 字节推导并记进 manifest 的 `minimumNodeMinor`；`ensureWorker` 在上传前拒绝过旧的远端 Node，并提示升级后重新探测。worker 以 `process.mjs` 上传，不能直接用 `.js`（ESM 解析问题）。
- `process.env` 为空；`cwd`/相对路径在远端。支持 per-call function-body、persistent-in-memory REPL 和 vm-script（scriptPersistence）；保留状态按 state owner 留在远端进程，沙箱模式变化时由官方 runtime invalidate。
- 上游契约、manifest 与升级 runbook 见 [upstream-ptc-worker.md](upstream-ptc-worker.md)。
- 如果远端 sshd 禁用 streamlocal，会尝试 loopback TCP；两者都不可用时明确失败，不静默回退本机。

## 远程运维细节

`ssh_workspace` 做一次远端 `stat`，再按远端真实路径注册（符号链接记成它指向的目录，标题默认取这个真实路径的目录名）。`realpath` 失败则这次注册失败。它不改远端文件。它只在侧栏加一条工作区。打开这条工作区会在那台机器上开始一个会话，所以询问策略下仍和命令一样要审批。这次调用不让当前会话进入，结果里也不给出占位目录。要在那台机器上工作，从侧栏打开。文件系统根 `/` 不能注册，真实路径解析成 `/` 时同样拒绝：那一棵会盖住整台机器。对同一个远端真实路径重复添加不会产生第二行，保留已有的标题，结果里会说明它已经注册过。

运维工具的前提：

- 目标主机必须已经在设置里信任过指纹，否则连接失败
- `ssh_exec` 用 `bash -lc`，会读登录 shell 的 profile，这样 `PATH` 里才有 `systemctl`、`docker` 这类命令；profile 若往 stdout 打东西，会出现在命令输出里
- `sudo` 只能走免密（`sudo -n`）。SSH 非交互执行没有 TTY，需要口令的 `sudo` 会卡住
- 只支持直连的 Linux 或 macOS；不支持跳板机和 Windows 远端
- 上传、下载和跨主机复制都只处理单个文件：不跟目录、不续传，单次上限和超时见上面的设置项
- 网络中断时，正在执行的远端命令会失败；已经写入的文件留在远端，不会回滚

## 侧栏终端

在远端工作区里，右侧栏的终端连的是那台服务器，不是你这台电脑：新建终端时 shell 菜单里列的是远端 `$SHELL` 和远端装了的 `bash` / `zsh` / `fish` / `sh`，标签名带主机名（`lo · zsh`）。缩放、滚屏、复制、刷新页面后重连都由 DSH 原来的终端界面负责。

- **连接是共享的。** 一个标签页一条 SSH 通道，和文件传输、远端命令共用这台主机的那一条连接。OpenSSH 默认 `MaxSessions 10`，而 DSH 每个会话最多 8 个终端。通道占满时新标签页会报这台主机拒绝再开一个 SSH 会话；只关侧栏终端不一定腾得出名额，也可以在远端调高 `MaxSessions`。
- **不跟随后续的 `working_directory`。** 已经开着的终端留在打开时那个远端目录；新开的用当时的目录。占位子目录不存在时，新建终端会先把它建出来，这样不会退回工作区根。建不出来时仍由 DSH 退回工作区根。
- **断线即结束。** 连接断了终端就结束，不会自动重连，也没有回滚：关掉标签页重开一个即可。
- **模型终端和侧栏是两条远端 PTY。** `terminal_open` 把 cwd 改写成当前主机的占位路径后调用官方工具。占位目录上的 `spawnTerminal` 都在远端执行；spawn bridge 由只依赖 `subprocess` 的独立注入安装，`sandbox.confine` 在另一条注入里安装。模型终端要求两者都就绪，如果 spawn bridge 或远端 world 没有装上，远端 `terminal_open` 会 fail-closed 报错，不会回退到本机 PTY；侧栏终端只要求 spawn bridge。侧栏仍是用户选的登录 shell；其余（包括 `dumb`）按官方 argv 和环境启动。启动前把 pid 和 `ps -o lstart=` 写到 `$HOME/.dsh-permission-remote/pty/`。每台主机共用一条探测 shell，不再为每次前台查询新开 SSH 通道；请求级取消只排空自己的 marker，不会关闭共享通道或拆掉其他会话（代价是被放弃的命令跑完前，同一台主机的下一次查询要排在它后面，最长 `PROBE_TIMEOUT_MS`）；捕获 pid、信号投递和清理使用一次性 exec，不占用前台探测通道。`inspectForeground` 只接受正数的前台进程组，`inputWaiting` 固定为 false；对不上 pid 文件、`ps` 失败，或 tpgid 不是正数时返回空，官方后端退回提示符和静默。由于 `inputWaiting` 恒为 false，精确的 stdin 等待不会成立，REPL/密码提示通常只能靠提示符证据或约 3 秒静默判定，最坏到 30 秒超时。`signalForeground` 用 `kill -s SIGNAL -- -<tpgid>`，不用 OpenSSH 不投递的 `channel.signal`；tpgid 为空、`0` 或 `-1` 时改为打记录下来的 pid，避免 `kill -- -1`；探测整体失败时回退到缓存的远端 pid，不再抛错导致官方把健康会话当 transport failure；SIGKILL 指向 shell 自身时明确拒绝。前台组已经退出、`kill` 没有打中时仍返回这个组号，取消发送不会因此拆掉会话。`terminate` 先向这棵进程树上还能看见的子孙发 SIGTERM，再打记录下来的进程，等宽限，再 SIGKILL，最后关通道。已经脱离这棵树的进程（两次 fork 之后）不会被打到。shell 自己退出时删掉 pid 文件；文件里的启动时间和活进程对不上时，后续信号直接放弃。`terminal_send` / `terminal_read` / `terminal_list` 仍只认已经打开的会话。远端需要 POSIX `sh` 和可用的 `ps -o`（Linux/macOS 默认满足；BusyBox/BSD 变体可能不支持），否则模型终端会在 pid 捕获阶段报错；侧栏终端不依赖这条 probe。pid 文件的身份校验使用 `ps -o lstart=` 的秒级文本；同一秒内的 pid 复用、或 PTY 与 probe 的 `TZ`/`LC_TIME` 不一致时，校验可能偏保守地让探测或信号回退到记录 pid，而不会误杀无关进程。异常断线或卸载时，`$HOME/.dsh-permission-remote/pty/` 下的 pid 文件仍可能残留；后续探测会先校验启动时间，不会直接信任它。

## 可选的 `apply_patch` / `str_replace_editor`

DSH 0.2.2 还有两个可选的文件工具，在远端工作区里同样落在这台机器上。两者默认都关着，插件不会替你启用，要在预设或组合里自己打开：把 `@deepseek-ai/dsh-tool-fs` 的 `applyPatch` 设为 `true` 才注册 `apply_patch`（所有官方预设都默认 `false`）；`@deepseek-ai/dsh-tool-str-replace-editor` 是独立包，只在自定义组合里挂载，官方预设不带它。

路径写法：

- `apply_patch` 的路径按会话工作目录（本机占位目录）解析，也可以直接给绝对占位路径，或直接写远端真实绝对路径（例如 `/srv/app/a.ts`，按远端主机解析）。
- `str_replace_editor` 只收绝对路径：把 `read` 或右侧栏文件树返回的占位路径原样传回去。若给了它一个远端真实绝对路径，插件会把它改写成同一台主机对应的占位路径，绝不会在本机按这个名字读写文件；若该工具的转发层没有挂载，这类调用会被直接拒绝，同样不会碰本机文件。

行为：`apply_patch` 的新增、更新、删除、移动，和编辑器的 `view`、`create`、`str_replace`、`insert`，都在远端执行，并遵守会话的 Permissions 档位、审批卡片和远端沙箱，删除与移动也不例外。整个补丁先整体预检，再按顺序逐条提交；中途失败不会回滚，已提交的操作留在远端。一次「移动」若已发布目标、却删不掉源文件，目标保留，调用只报告这一步失败。

限制：只处理 UTF-8 文本，不支持二进制；没有回滚。`str_replace_editor` 没有一次性的 `sandbox_permissions` / `justification` 提权，请用会话里已经设好的常驻 Permissions 档位。移动涉及两个路径，不是原子操作；删除只涉及一个路径。

**行尾风格。** `edit` 和 `apply_patch`（含更新与移动）改文件时，会把读到的内容按 LF 处理，写回时按文件开头的 4096 字节判断原本是 LF 还是 CRLF，再整体转回同一种风格。因此混合行尾的文件（前 4KB 是 LF、后面是 CRLF）会被整体统一成开头那种，不只改动你编辑的那一行。`write` 不参与这套转换：传进去的字符串按原样落盘，CRLF 原样保留；只是返回给模型的 `after` 会统一按 LF 归一化。这与本机的 `dsh-fs-local` 逐字节一致（它的 `writeText` 也是原样写入，只有 `editText` / `patchText` 做行尾还原），是刻意的行为对齐而不是远端特有；若不想让整份文件被转换，改文件前先统一行尾，或直接用 `bash` 里的工具处理。

## 其它实现说明

**左侧文件列表与右侧文件树。** 对话里的读文件、改文件、搜索和运行命令发生在远端。左侧的文件列表，以及输入框里的 `@` 补全，仍用本机文件系统扫占位目录，列不出远端文件。右侧栏的文件树列出远端目录里的内容，标题仍是这条占位路径，自动刷新不可用。手动刷新会再向远端要这一层的名字。远端 `bash` 工具的进程结束后，这台主机上缓存的文件属性会清掉。侧栏终端、`ssh_exec` / `ssh_write` / `ssh_upload` / `ssh_download` 和「运行代码」没有这条边界，文件是否存在、大小这些属性在大约 5 秒内可能仍是刚才的结果。用户上传的非图片文件会先复制到远端 `~/.dsh-permission-remote/uploads/`，单文件大小和超时用设置页的「单次传输上限」和「单次传输超时」：默认 32 MiB、120 秒。字节填 `0` 只取消字节上限，默认超时仍然生效。复制前会先看本机文件的实际大小；真正复制分段进行，同时在途大约 1 MiB。传到点会记一条带毫秒数的警告，对话继续。60 秒内同一份上传不会整文件重传，但会再确认叶子不是符号链接。模型看到的是远端绝对路径。

**Windows 上的 DSH。** DSH 本身跑在 Windows 上时，远端工作区的对话只暴露远端 `bash`。`pwsh`、`powershell`、`cmd` 不会出现在原生工具列表里，官方那段 Windows 进程结束说明（`tool:pwsh`）在停在这个工作区时也会被盖住。回到本机目录后，这些 Windows 工具和原来的说明恢复。`minimal` 这类把提示词写成完整 persona 的预设不会被改写；挡住 Windows shell 的是工具列表过滤和执行守卫。内置预设的 `pwsh` 在祖先层，进入远端时会被从原生工具列表和 `ptc` SDK 正文里去掉。注册在 agent 本层的 `pwsh` 去不掉：SDK 正文仍可能列出它，原生列表会被滤掉，调用会被拒绝。文件工具的参数继续用工具返回的占位路径。

**运行代码与项目说明文件。** 模型用「运行代码」时，如果会话的工作目录是远端占位目录，程序由 SSH 主机上的官方 PTC worker 执行，不是本机那份；本地会话仍然在本机执行。会话读取项目里的 `AGENTS.md`、`CLAUDE.md`（以及同名的 `.local`）时走文件系统接口，占位路径会读到远端那一份。`$DSH_HOME/AGENTS.md` 这种不在占位根下的全局文件仍是本机。每轮组装提示词会沿祖先目录对这些文件多做几次远端查询。提示词内容和本机那份不一样，已经缓存的前缀对不上。

**连接边界。** 目前只能直接连接一台 Linux 或 macOS。不能经跳板机连接，也不能把 Windows 当作远端。网络中断时，正在进行的操作会失败。已经写到远端的文件会留在那里：重新连上之后不会再写一遍，也不会自动撤回。远程工作区里的 `bash`、`read`、`write`、`edit` 只能操作那台机器；要在当前本地工作区操作另一台主机，用 `ssh_hosts` / `ssh_exec` / `ssh_read` / `ssh_write` / `ssh_upload` / `ssh_download` / `ssh_copy` / `ssh_workspace`。要在两台远端主机之间搬文件，用 `ssh_copy`：字节从源主机的 SFTP 通道直接流到目标主机，不经过本机磁盘。

**Linux 沙箱。** 要让命令遵守当前权限，需要在那台机器上安装 bubblewrap。设置页可以代为安装，页面上也有可以自己执行的命令。
